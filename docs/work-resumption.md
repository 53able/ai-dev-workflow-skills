# 中断した変更を再開する

同じプロジェクトで Claude Code または Codex を開き、再開する変更ディレクトリを指定して `ains` に依頼します。仕様・計画・残作業をファイルから確かめることで、長い会話を読み直さずに再開できます。

## まず状態だけ確認する

製品の会話欄に入力します。`<変更ディレクトリ>` は実際のパスへ置き換えてください。

```text
Claude Code: /ains <変更ディレクトリ> の状態と、次に必要な判断を教えてください。
Codex:       $ains <変更ディレクトリ> の状態と、次に必要な判断を教えてください。
```

状態確認だけではファイルを変更しません。対象を省略すると最新の変更が推奨されますが、それだけで実行対象にはなりません。

## 続行を依頼する

使う製品のコマンドを選び、次のように依頼します。

```text
/ains <変更ディレクトリ> を再開してください。
spec.md と tasks.md（ある場合）、メモ、現在の差分を確認し、
承認済みの範囲と記録された操作権限で、残る工程を進めてください。
未解決の判断があれば、その内容を示してください。
```

Codexでは先頭を `$ains` に置き換えます。「この実装だけ」など工程を限定した場合は、その工程までで終わります。

| 記録の状態 | 再開する工程 |
|---|---|
| プロジェクト設定がない | `ains-setup` |
| specがdraft・未決事項がある | `ains-spec` |
| specはapproved、計画がない・draft | `ains-tasks` |
| 承認済みのタスクが残る | `ains-build` |
| タスクがすべて完了 | `ains-ship` |

小さな変更はspecにタスクをまとめるため、tasks.mdがない場合もあります。ファイルの `approved` 表示だけから新しい作業依頼や操作権限を推測しません。既存の承認は同じ内容・範囲で保持し、仕様を変える場合は仕様と計画をdraftへ戻して判断し直します。

## 会話を切り替える前に残すこと

会話が長くなったり、同じ失敗を繰り返したりしたら、`ains-context-care` の引継ぎ手順を使います。tasks.mdの「メモ」（小さな変更はspec.md）に、次を残してください。

- 決定したことと理由、守る制約、任せた操作の範囲
- 完了したタスクと、実行した検査・結果
- 残作業、試して失敗したこと、未解決の質問

新しいセッションではspecとtasksを読み、重要な制約を冒頭で確認します。失敗した検査を実行済みの成功に変えたり、古い承認を変更後の仕様へ流用したりしないでください。

## 再開できないとき

| 困りごと | 確認すること |
|---|---|
| スキルが見つからない | 利用先プロジェクトで全16スキルが導入されているか。[導入手順](../README.md#導入)を確認 |
| 設定が食い違う | AGENTS.mdのAgent skills節とCLAUDE.mdの参照。`ains-setup`で相違点を確認 |
| どの変更か決められない | 再開したいディレクトリを1件指定 |
| 検査が失敗する | 失敗内容と範囲を確認。完了扱いにせず、許された範囲で修正 |
| 独立レビューができない | 別セッションへ引継ぎ。レビュー未完了として出荷判断を保留 |
| コミットや公開で止まる | 既存の許可と今回の範囲を確認。工程続行だけで許可を増やさない |

## このスキル群自体の検証状況を知りたい場合

以前の開発では、Codexの終了処理・質問・設定移行などで失敗や保留があり、旧基準での全体検証は未完了です。その後の社内試用では以前の版の16スキル×両製品の実行記録が揃いましたが、人の最終確認、現行の自動続行、変更後のteam-canvasの確認は残っています。導入判断には [対応範囲と制限](compatibility.md)と [試用確認一覧](internal-trial-validation.md)を使ってください。
