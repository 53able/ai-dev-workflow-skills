# はじめて使った人の確認シート

**実施状況：未実施（NOT_RUN / HUMAN_PENDING）。** [練習手順](getting-started.md)を初めて使う人が、作者の補足なしで進められるかを確かめるシートです。参加者と実施結果はまだありません。

対象は、Gitとターミナルを使えて、AI開発には不慣れな開発者です。参加者は案内に沿って操作し、観察者は迷った箇所と支援の有無を記録します。AIによる通読や模擬操作、[試用結果32項目](internal-trial-validation.md)の人による確認とは区別します。

- 製品・版・モデル／OS：未記入

- 本人に伝える範囲：使い捨てプロジェクトのみ。秘密情報・業務データを入力せず、外部PR・push・マージ・デプロイはしない
- 観察者：未記入。口頭で手順を先回りして教えない。支援したら下表へ記録する

## 参加者に依頼すること

1. [README](../README.md)から入口を見つけ、案内だけを使って練習用プロジェクトを作り、一括導入と初回設定を行う。
2. 負の整数を渡しても返り値が0未満にならない変更のspecをdraftで作る。まだ承認せず、「何を作るか／何を変えないか／AIに何の操作を任せたか」を自分の言葉で説明する。
3. 新しい会話で再開し、ファイルの状態から次の工程を見つける。specがdraftの間は実装せず、承認待ちで止まることを確認する。
4. spec全体を確認して承認した後、実装からローカル出荷資料まで進める。
5. 検査出力と変更ファイルを読み、レビュー未完了・人の判断待ち・テスト失敗を区別する。
6. 案内にある `UNVERIFIED / 3` を見たつもりで、何を調べ、どこで止まるか説明する。故障や秘密情報の入力を実際に起こす必要はない。

途中で進めなくなったら、その箇所と次に期待したことを記録する。観察者が助けた場合も継続してよいが、「作者の補足なしの成功」にはしない。
