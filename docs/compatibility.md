# 導入前に確認する対応範囲と制限

ains は Claude Code / Codex 向けの16スキルです。現在は社内・チームでの試用段階です。まず [練習用プロジェクト](getting-started.md)で、使う製品と設定に合うか確かめてください。

## どこまで確認されているか

| 項目 | 確認範囲と利用上の注意 |
|---|---|
| 導入方式 | 全16スキルをプロジェクト単位で一括導入。リンク・コピー配置を検査済み |
| 対象製品 | Claude Code / Codex。両製品の正式な実行時サポート確認は未完了 |
| 試用結果 | 以前の版では16スキルを両製品で各1回使った32項目の記録あり。人による成果の最終確認は未了 |
| 現行の工程続行 | v0.5.0で変更。承認後の自動続行は新しい検証対象で、旧版の成功を現行版の動作証拠には使えない |
| チーム合意 | `ains-team-canvas` は合意記録の手順へ変更後、両製品での実機再確認が未実施 |
| 初めての利用者 | 作者の補足なしで導入・完了できるかの確認は未了 |
| OS・他製品 | 記録はmacOS環境。他OS・他エージェント・個別スキルだけの導入は未検証 |

32項目は複数時期・版の記録を合わせたものです。反復成功率、実務での効果、現行ソース全体の成功を示しません。詳細は [試用確認一覧](internal-trial-validation.md)にあります。

## 導入と更新で守ること

導入コマンドと前提は [READMEの導入](../README.md#導入)を参照してください。配布確認に使った skills CLI は1.7.4です。CLIの版を変える場合は、helpと配布検査、利用製品での動作を改めて確認します。

Claude Code は `.claude/skills/`、Codex は `.agents/skills/` から参照します。スキル内の assets・scripts・参照Markdown・agents設定も必要です。開発用evalやfixtureは導入対象に含めません。

設定の正本は `AGENTS.md` の「Agent skills」節です。Claude Code は `CLAUDE.md` の `@AGENTS.md` から読みます。`ains-setup` は次の扱いで既存設定を移行します。

- 既存の値と無関係な文章を保持し、同じ節やimportを増やさない。
- 値が食い違う場合は、利用者が残す値を選んでから統合する。
- 同一実体には一度だけ書き、自己importや循環を作らない。
- 既存の「各工程は手動起動のみ」という方針は、利用者が変更を明示するまで保持する。

主要5工程をエージェントからも呼べるようにした変更は、起動契約の破壊的変更です。自動続行へ移す場合は、`ains-setup` に起動方針の置換を明示してください。再導入だけで操作権限や既存方針を変更することはありません。

## 自動で進む範囲

`/ains`（Codexでは `$ains`）だけなら、ファイルを変えず状態と次の工程を示します。対象を指定して一連の実行を依頼した場合は、仕様・計画の承認後に同じ範囲の工程を続けます。個別工程を依頼した場合は、その工程までです。

起動や参照は操作の許可を増やしません。コミット、push、PR作成、マージ、デプロイは、それぞれ利用者が任せた範囲に従います。対象が曖昧、未承認、範囲変更、検査失敗、独立レビュー未完了なら、その工程の停止条件に従います。

明示起動限定の入口・補助工程の設定は、製品のネイティブなスキル起動を制御します。通常のファイル参照を遮断するセキュリティ機構ではありません。

## 既知の制限と対処

| 状況 | 対処 |
|---|---|
| 質問UIを使えない | 短いテキスト質問を1つずつ受け、回答する |
| 独立したレビュー手段がない | 別セッション向けの引継ぎを使う。自己点検を独立レビューの完了に数えない |
| 仕様・計画を承認していない | 案を確認して回答する。`approved` の自己記入だけで承認を代替しない |
| 規約が守られない | 配置・読込・矛盾・会話の圧縮を点検する。[再開ガイド](work-resumption.md)を参照 |
| 規制対象のシステムで使う | 規制が求める保証工程を別途維持する。ainsだけで代替しない |

## 過去の検証から分かること

配布検査の成功と製品上の行動検証は分けて扱います。過去のFAIL・保留・未検証は、新しい限定成功によって成功へ読み替えません。

- Claude Code 2.1.310の記録では、限定したmacOS設定で、仕様・計画・実装・取り消し・独立レビュー・ローカル出荷準備などの複合受入に成功しました。現行の自動続行や両製品全体の保証ではありません。
- Codexでは設定移行の6形状と一部の質問・実装などに限定成功があります。一方、通知仕様の承認質問欠落、実装の終了失敗、全体フロー未完了、検査生成cacheによる厳密な全状態一致ゲートの保留が記録されています。旧全体試験の完了を主張できません。
- 2026-10-29の自動採点では、最終のゲート系9ケースはClaude Codeで9件、Codexで7件が全試行合格でした。Codexのtasksと独立レビュー未提供時のケースは未達です。レビューの引用規定を戻した再計測はClaude Code 5/5、Codex 2/5でした。
- 2026-11-02の設計規則の比較では、新規4ケースのうちClaude Codeはretro、Codexはtasks・build・retroが合格しました。reviewはClaude Codeで前後差を識別できず、Codexではサブエージェントを観測できず測定不能でした。既存ケースで回帰候補はありませんでしたが、各N=3の限られた測定です。

自動採点ではCodexの `.git` 書込制限など、製品・実行環境による偏りもあります。人による確認の代わりにはなりません。条件・判定・限界は次の記録で確認できます。
