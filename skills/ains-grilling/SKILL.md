決める前に質問で認識を揃える。事実を調べるのはAI、決めるのは人。

## 進め方

1. 先にコード、文書、設定を調べる。調べれば分かることは質問にしない。
2. 決めることを木として捉える。前提が決まっていて今すぐ聞ける問いの集まりが**前線**になる。
3. 複数の判断を一度に聞けるのは、実際に構造化質問ツールを呼ぶ場合だけとする。平文で回答を求めるときは、ツールの有無にかかわらず、最も判断を進める独立した質問を1つだけ聞く。推奨案と理由を1行で添える。
4. 回答を受けて前線を更新し、次のラウンドへ進む。前線が空になったら終える。

利用できる構造化質問ツールがあれば、選択肢つきで聞き、推奨案を先頭に置く（Claude Code の AskUserQuestion、Codex の利用可能な質問ツールなど）。ツールがない、または現在のモードで使えない場合は、簡潔な質問を1つ会話に書き、回答を待つ。ツールの不在、無回答、時間の経過から承認を推測しない。同じ範囲について既に明示された回答・承認は引き継ぎ、同じ判断を繰り返し求めない。

平文を送る前に、回答を求める独立した判断が1つだけかを点検する。「あわせて」や追伸で別の判断を足さない。他の未決事項は作業メモに残し、今の返信では回答を求めない。実際の USER の回答を待ってから次を選ぶ。

平文で回答を求めるときは、その質問をその回の最終応答に書いて止まる。途中の報告に質問を書いたまま作業を続け、別の文で締めくくらない。最終応答だけを読んで、何を決めてほしいかと推奨案が分かるようにする。ファイルへのリンクや「上の質問」への参照だけで済ませない。

## 上限

質問の上限はここだけに置き、他のスキルはこれに従う。

- 1回の構造化質問は5問まで。UIの上限がそれより小さければ、UIの上限まで
- 承認を求めるとき（仕様・計画の承認、ship での判断依頼）に一度に示す判断点は3つまで。判断点は、人に決めてもらう未決の点を数える。ains-spec 5. の解決済みの内容の要約は判断点に数えず、その節の3点以内の規定に従う。超えるなら、承認を求める前に、先に決められる点を前線の質問として聞いて決め、残りが3つ以内になってから承認を求める
- 前線を空にするための質問は5問までの上限に従い、ラウンド数は制限しない

## 平文での例

```
既存利用者の既定値はONでよいですか？
推奨：ON。現在の送信動作を保つためです。
```

## 完了条件

前線が空になり、決まったことを一覧で示して人が「この理解でよい」と答えた。
「任せる」と答えた問いは、推奨案を仮定として記録する。
