手動で使うときは、Claude Code では `/ains`、Codex では `$ains`（各段階も同様に `/ains-spec` / `$ains-spec`）。本文のスキル名は製品に依存しない手順名であり、「次」は人への案内を示す。Claude の手動専用スキルをモデルが起動できるという意味ではない。起動設定は操作の許可や業務上の承認を与えない。

## 1. 状況を見る

- AGENTS.md / CLAUDE.md に「Agent skills」節があるか
- 変更ディレクトリの状態：`<このスキルのディレクトリ>/scripts/status.sh [<変更の置き場所>]`
- 利用者が今言っていること

推奨を1つ、理由を1行で示す。迷う場合だけ候補を2つまで並べる。各スキルの中身を説明するときは、その SKILL.md を読んでから答える。

通常の Read/Bash 等による手順・資産の参照は、依頼と権限の範囲で行え、追加承認は不要。参照は製品ネイティブのスキル起動とは別で、操作の許可や仕様・計画の承認を与えない。手動段階のネイティブ起動は利用者の明示的なコマンドに限る。次段階の推奨、approved、AIの提案だけでは次をネイティブ起動しない。利用者が明示して続行した同じ範囲では、再度許可を求めず進める。

## 2. 主な流れ

アイデアを作って出荷するまで。上から順に見て、最初に当たるものを選ぶ。

1. Agent skills 節がない → `ains-setup`（リポジトリごとに1回）
2. 新しく作りたい・直したいという依頼で、既存の変更に当たらない → `ains-spec`
3. マージ・展開を終えた、または本番で問題が出たと利用者が言う → `ains-retro`
4. それ以外は、対象の変更の状態で決める。対象は利用者が指した変更、指していなければ status.sh の先頭行（最新の変更）。

| 対象の変更の状態（status.sh） | 次 |
|---|---|
| spec が draft | `ains-spec` |
| spec が approved、`plan=-`、`tasks=0/0` | `ains-tasks` |
| `plan=draft` | `ains-tasks`（計画の承認が先。タスクが完了していても同じ） |
| 未完了のタスクがある | `ains-build` |
| タスクが1件以上あり、すべて完了 | `ains-ship` |
| どれにも当たらない | status.sh の行を示し、次にしたいことを人に聞く |

小さな変更（spec の「タスク」節にタスクがあり `plan=-`）は、build か ship の行に当たる。

1行の修正やタイポは流れに乗せず、直して検査を実行する。マージ前の ains-review-gate の判定はこの場合も行う。

## 3. 流れの外

| 状況 | 使うもの |
|---|---|
| チームでAIの使い方を揃えたい | `ains-team-canvas` |
| レビュー待ちや不具合の流出が増えた、CIを見直したい | `ains-harness` |
| MCP や CLI をエージェントに使わせたい | `ains-tool-access` |

次のスキルは、エージェントが必要に応じて自分で使う。名前を指定して呼んでもよい。

| スキル | 役割 |
|---|---|
| ains-grilling | 質問で認識を揃える |
| ains-tdd | テスト先行の実装 |
| ains-review | 別セッションの敵対的レビュー |
| ains-review-gate | 人の確認が必須かの判定とマージ条件 |
| ains-release-safety | 展開、フラグ、戻らない状態変更 |
| ains-context-care | 規約無視の診断、引継ぎ、ルールの整理 |
