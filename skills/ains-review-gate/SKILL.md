人の確認が要るかは、AIの印象ではなく規則で決める。規則に当たった変更は、テストが通っていても、AIが低リスクと見ても、人が確認する。

## 1. 規則で判定する

先に依頼されたレビュー対象とマージ先を確かめ、対象のコミットを現在の HEAD と比較する。現在の作業（未コミットを含む）は、リポジトリ内から検証済みのインストール先の絶対パスで実行する。

```bash
<インストール済みスキルの絶対パス>/scripts/route-review.sh docs/ains/human-review-rules [base-ref]
```

別の明示されたコミット済み対象（例：main 上で feature/cleanup をレビュー）には第3引数を使う。チェックアウトは変えない。

```bash
<インストール済みスキルの絶対パス>/scripts/route-review.sh docs/ains/human-review-rules main feature/cleanup
```

第3引数モードは merge-base..head のコミット済み変更だけを調べ、解決した base/head/merge-base を表示する。現在の index・作業ツリー・未追跡や追加の未コミット対象は含まない。対象や必要な範囲が不明・曖昧・不完全なら UNVERIFIED として示し、現在の HEAD や手動の規則照合で必要な helper の判定を代用しない。

| 終了コード | 判定 | 扱い |
|---|---|---|
| 10 | HUMAN_REQUIRED | 一致した領域の確認者が承認するまでマージしない。「規則ファイルが base に無い」は規則ファイルの変更を承認する人、「サブモジュールの変更」は参照先のリポジトリの担当者が確認する（誰かは ains-team-canvas の合意記録「担当・相談先」で決める。未定なら作業を依頼した人） |
| 0 | NO_MANDATORY_MATCH | 2. へ |
| 3 | UNVERIFIED | 人へ回す（規則なし、差分0件、書式不正、差分を取得できない） |

base-ref は PR のマージ先にする。規則は base の版を使うので、規則の追加はマージ後の変更から効く。

規則ファイルが無ければ、[assets/human-review-rules.example](assets/human-review-rules.example) を見せ、`docs/ains/human-review-rules` として置くかを人に聞く。置くまでは UNVERIFIED として扱う。path の照合は大文字小文字を区別しない。

## 2. 規則外はリスクを評価する

[risk-scorer.md](risk-scorer.md) の手順で、low / medium / high と推奨（自動統合可／1人確認／複数人確認）を出す。迷う観点があれば高い側へ倒す。評価は確認を足せるが、1. の判定を外せない。

## 3. 結果を示す

判定、一致した規則、確認すべき人、規則外ならリスク評価を、PR 本文か会話に示す。人が確認する変更では、確認者は差分を読む。必須確認の変更では、加えてコードとデータの流れを読む。規則外の変更は what_could_go_wrong から読み始める。

DB移行・削除など戻らないデータ変更があれば、判定にかかわらず隣の [ains-release-safety の手順](../ains-release-safety/SKILL.md) を読み、その「戻らない状態変更」を今回の差分に適用する。人への結果には、単に「危険」「バックアップを確認」ではなく、次の具体策と検証結果（未実施ならその旨）を含める。

- 消える列・行と主キー、移行先・対応関係を特定し、削除前の退避と移行前後の件数・値・欠損の照合方法を示す。例：列削除では旧値を主キー付きで保持し、移行が必要か未使用かを参照元とデータで確かめる
- バックアップの対象・取得時点と、隔離環境での復元試験・復元値の照合を示す。バックアップがあるだけで復元可能と扱わない
- expand-contract（追加 → バックフィルと照合 → 新旧互換のコードへ切替 → 安定確認後に旧構造を削除）に分け、各段階の中止条件を示す
- アプリだけを戻せる段階と、削除後にデータ復元または前方修復が必要な段階を区別し、復元元、手順、移行後の書込みを失わない対処を示す。未決の移行方針や未検証の復元を、解決済みとして扱わない

## マージの条件

次がそろうまでマージしない。

- 1. の判定に応じた人の承認がある
- 必須の CI が通っている
- マージが Agent skills 節の外向き操作の規則で許されている（既定は人の指示）

## 完了条件

判定と確認すべき人が示され、マージの可否とその理由が述べられている。
