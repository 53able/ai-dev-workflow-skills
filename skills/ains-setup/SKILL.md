# ains-setup：プロジェクトの前提を揃える

導入後に、検査コマンド・変更記録の置き場所・任せる操作・人の確認の規則を揃えます。成果はプロジェクトの設定です。


最初に [実行範囲と工程の続行](../ains/workflow.md) を読み、今回の依頼が単独工程か一連の作業かを確かめる。以下の承認・停止条件を守り、一連の依頼では完了後に次へ進む。

ほかの ains スキルが毎回聞かずに済むよう、前提を一度だけ決めて記録する。

## 1. 調べる

- `AGENTS.md`、`CLAUDE.md` と、その中の「Agent skills」節、既存の import。シンボリックリンクは `test -L` とリンク先、同一実体は `[ AGENTS.md -ef CLAUDE.md ]` で確かめる。リンク・import をたどるときは訪問済みの実体を記録し、循環をたどり続けない
- 検査コマンド：package.json の scripts、Makefile、CI 設定、pyproject.toml など
- 仕様の置き場所：`openspec/`、`.specify/`、`specs/`、`docs/specs/`、`docs/changes/`。機能単位の現行仕様が見つかれば、その置き場所も Agent skills 節に書く
- `docs/ains/human-review-rules` の有無
- 認証、課金、移行、基盤、CI のディレクトリ

## 2. 確認する

分かったことを示し、未決の項目だけ、ains-grilling の質問手順で推奨案を添えて聞き、回答を待つ。既存の設定・明示された承認は同じ範囲で保持し、調べて決まった項目や既に回答された判断は聞き直さない。既存の許可を下の既定で狭めたり広げたりしない。

以下は確認する話題の一覧で、同時に聞く質問ではない。質問の形と上限は ains-grilling に従う。既に解決した内容は要約し、了承が必要ならその要約への承認質問を1つだけ行う。未決の質問を要約に混ぜてまとめて承認させない。

1. **検査コマンド**：見つけたコマンド。無ければ何で確かめるか
2. **変更の置き場所**：`docs/changes/`。SDDの道具との役割の分け方は ains-spec の [sdd-tools.md](../ains-spec/sdd-tools.md)
3. **人の確認の規則**：このスキルの隣の ains-review-gate にある `assets/human-review-rules.example` を、1. で見つけたディレクトリに合わせて調整した案

操作の許可は、既存の明示的な許可と現在の利用者の明示的な制限を上限とする。新規の既定は編集とローカルの検査だけとし、コミット、push、PR、マージ、デプロイなどの許可は、操作と範囲への個別の明示的な付与がある場合だけ記録する。雛形や一般的な「setupを承認」は、新たな操作権限を付与しない。今回だけの制限は今回の実行範囲に適用し、恒久方針の変更指示がなければ既に明示的に許可されたプロジェクト設定は変更・再承認しない。相談先は下の既定で書き、利用者が変えたいと言ったときだけ書き換える。規制対象のシステムでは、ains は規制が求める保証工程を代替しないことを伝える。

## 3. 書く

正本は `AGENTS.md` の「Agent skills」節とし、Claude Code には `CLAUDE.md` の対応する import 行 `@AGENTS.md` で読ませる（コードブロックの外に独立した行として書く）。下の雛形は新規・未設定の項目だけの既定である。

書く前に両方の実体と管理対象の節を比較する。「Agent skills」節はその見出しから次の同階層以上の見出しの直前までとし、他の節や前後の文章はそのまま残す。

- **CLAUDE.md だけに節がある**：承認済みの値を保ったまま、その節だけを AGENTS.md へ移す。CLAUDE.md の元の節を `@AGENTS.md` に置き換える。既に同じ import があれば重複させない。
- **AGENTS.md だけに節がある**：その内容を保持し、CLAUDE.md に import を足す。
- **どちらにも節がない／ファイルがない**：AGENTS.md と節を作り、CLAUDE.md もなければ import の1行で作る。既存ファイルには必要な箇所だけ追記する。
- **同じ設定の節が両方にある**：AGENTS.md を正本として1つ残し、CLAUDE.md の重複節だけを import に置き換える。既存 import は1つに保つ。
- **設定が食い違う**：変更前に相違点を示し、「どちらの値を残すか」を1つの焦点を絞った質問で聞く。回答を待ち、両方の節を上書きしない。自分で権威を選ばず、回答後に選ばれた設定へ統合する。

シンボリックリンクは通常はリンクを保って実体へ書き、同一実体には一度だけ書く。AGENTS.md と CLAUDE.md が同じ実体なら、節を1つ残すだけで両者から読めるため、自己 import は足さない。既存の `@AGENTS.md` が同じ実体への自己 import になる場合は、その行を除いて循環を解消する。AGENTS.md から CLAUDE.md を経由して自身へ戻る import も作らない。既存の逆向き import で循環する場合は、管理対象の設定移行に伴う辺だけを外し、それ以外の import・文章は保持する。循環リンクやリンク切れで実体を安全に確定できない場合は書かず、修復先を1問で確認して待つ。

移行だけで設定内容が変わらないときは既存の承認を保持する。再実行では同じ節・import・規則ファイルを増やさず、同じ内容を書き直さない。

```markdown
## Agent skills

- 検査：`<コマンド>`（タスクと変更を閉じる前に実行する）
- 変更の置き場所：`docs/changes/`
- 人の確認が必須の変更：`docs/ains/human-review-rules`（ains-review-gate が判定する）
- AIに任せる操作：編集、ローカルの検査（利用者の明示的な制限内。追加の操作には、その操作と範囲への明示的な許可が必要）
- 外向き操作（push、PR、マージ、デプロイ、外部への送信、本番データの変更）：人の指示で行う。例外は、利用者が操作と範囲を明示的に許可した tasks.md の「任せる範囲」と、チームが明示的に許可した自動統合の段階だけ
- 止まったときの相談先：<人・チャネル。空欄可>
- 費用・時間の上限：<1タスクあたり。あれば>
- 現行仕様の置き場所：<あれば>
- スキル起動：ains は明示起動の入口。状態確認だけなら案内し、一連の実行依頼では対象を一意に決め、setup/spec/tasks/build/ship を承認と任せる範囲に従って続行する。工程単独の依頼はその工程まで。仕様・計画・出荷の判断と停止条件は保ち、起動や参照から操作権限を増やさない。retro・harness・team-canvas・tool-access は明示依頼時に使う
- 次に何をするか迷ったら Claude Code では `/ains`、Codex では `$ains`
```

人の確認の規則を `docs/ains/human-review-rules` に書く。既存の規則は保持し、内容の変更が必要なときだけ差分を示して判断を得る。

既存の Agent skills 節に各工程の明示起動を求める規則がある場合は、上の雛形で上書きしない。自動続行への移行を求められたら、起動方針だけの変更案を示し、利用者が変更すると明示した範囲で反映する。編集・コミット・外向き操作の既存の許可は変えない。

## 完了条件

AGENTS.md に正本の Agent skills 節と規則ファイルがあり、CLAUDE.md の import（同一実体なら直接）から同じ設定を読める。循環や重複がなく、人が内容を了承している。
