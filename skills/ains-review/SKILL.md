実装したセッションは自分の答えに同調しやすい。新しい文脈のレビュアーに、欠陥がある前提で探させる。

## 手順

1. 利用可能なサブエージェント、または別の実セッションを、新しい文脈で起動し、[review-prompt.md](review-prompt.md) の指示文を渡す。実装中の会話を継承させず、渡すのは spec、差分、周辺コード、検査結果だけにする。別の文脈で実際にレビューが行われたことと、その結果を記録する。記録できるのは、この会話のツールで実際に起動して結果を受け取ったレビューか、人が示した別セッションの結果（実行した者、対象の base と head、結果の本文があるもの）だけだ。どちらにも当たらないレビュアーや結果を書かない。記録（変更ディレクトリの review.md）には、起動したツールの種類と引数の要点、返った応答の該当部分、または人が示した結果を原文のまま引用する。引用できないものは、レビューとして記録しない。完了を示す言葉は、完了条件を満たしたときだけ使う。満たしていなければ「独立レビュー未完了」と報告する。
   独立した実行手段がなければ、これらの資料と指示文を引継ぎ用にまとめ、「独立レビュー未完了」と報告して止まる。同じ会話で役割を変えた自己レビューを、独立レビューの合格として扱わない。
2. 返った指摘を選別する。

| 確認の結果 | 扱い |
|---|---|
| 再現できた、またはコードで根拠を示せた | 直す |
| 根拠を示せない、仕様と関係がない | 採らず、理由を残す |
| 人の知識が要る | 人に示す |

3. 直したら、影響する検査をやり直す。
4. 往復は2回まで。それで収束しなければ人に見せる。

並列に作った成果は、統合した後の状態でレビューする。

## 完了条件

別の文脈での実レビューが完了し、blocker の指摘がなく、採らなかった指摘には理由がある。引継ぎを準備しただけなら未完了。
